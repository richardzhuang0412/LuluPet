# 噜噜桌宠 · Firebase 设置和安装说明

两台 Mac 上的宠物要互相串门、发消息，需要一个"中转站"。我们用 Google 的免费服务
**Firebase Realtime Database（实时数据库）**。只需要设置一次，大约 10 分钟。

> 只需要**一个人**做第 1～4 部分，然后把"数据库网址"发给对方即可。

---

## 第 1 部分：创建 Firebase 项目

1. 用浏览器打开 <https://console.firebase.google.com>，用你的 Google 账号登录。
2. 点 **创建项目**（英文界面是 **Create a project** / **Get started with a Firebase project**）。
3. 项目名称随便填，比如 `lulupet`，点继续。
   - 如果提示接受条款，勾选后继续。
   - 如果问要不要开启 **Gemini in Firebase** 之类的 AI 助手，可以关掉，不影响。
4. 问要不要启用 **Google Analytics（谷歌分析）** 时，**关掉**它（用不上），然后点 **创建项目**。
5. 等转圈结束，点 **继续**，进入项目主页。

## 第 2 部分：创建实时数据库

1. 在左侧菜单找到 **Databases & Storage（数据库和存储）** → **Realtime Database**。
   - 旧版界面里它在 **Build（构建）** → **Realtime Database**，两种都一样。
   - 找不到的话，左上角搜索框里搜 "Realtime Database"。
   - 注意：不要选 **Firestore Database**，那是另一个产品。
2. 点 **创建数据库（Create database）**。
3. **数据库位置**选 **United States (us-central1)**，点下一步。
4. 安全规则选 **以锁定模式启动（Start in locked mode）**，点 **启用（Enable）**。
   - 放心，下一步我们会换成自己的规则。

## 第 3 部分：粘贴安全规则

1. 数据库页面顶部有几个标签：**数据（Data）/ 规则（Rules）/ 备份 / 用量**。点 **规则（Rules）**。
2. 把编辑框里原有的内容**全部删掉**，粘贴下面这段（完整复制，包括最外层的大括号）：

```json
{
  "rules": {
    ".read": false,
    ".write": false,
    "pairs": {
      "$code": {
        ".read": "$code.matches(/^[A-HJ-NP-Z2-9]{24}$/)",
        ".write": "$code.matches(/^[A-HJ-NP-Z2-9]{24}$/)",
        "messages": {
          ".indexOn": ["ts"],
          "$id": {
            ".validate": "newData.hasChildren(['from','kind','ts']) && newData.child('ts').isNumber() && newData.child('ts').val() <= now + 86400000 && (!newData.child('text').exists() || (newData.child('text').isString() && newData.child('text').val().length <= 500)) && (!newData.child('stickerId').exists() || (newData.child('stickerId').isString() && newData.child('stickerId').val().length <= 64)) && (!newData.child('outfit').exists() || (newData.child('outfit').isString() && newData.child('outfit').val().length <= 64)) && (!newData.child('remind').exists() || (newData.child('remind').isString() && newData.child('remind').val().length <= 64)) && (!newData.child('answer').exists() || (newData.child('answer').isString() && newData.child('answer').val().length <= 64))"
          }
        }
      }
    }
  }
}
```

3. 点右上角的 **发布（Publish）**。看到"规则已发布"之类的提示就成功了。
   - 如果编辑框出现红色报错，多半是复制时少了括号，重新整段复制一次。
   - 页面上可能会有一条黄色警告说"规则允许公开访问"之类的，可以忽略：
     只有知道 24 位配对码的人才能读写你们的数据。

这套规则的意思（不用看懂也行）：

- 整个数据库默认谁都不能读写；
- 只有 `pairs/<配对码>` 这一格可以读写，而且配对码必须正好是 24 位、只含噜噜桌宠用的那些字符（猜不到，也塞不进乱七八糟的路径）；
- 每条消息必须带发送人、类型、时间（时间必须是数字，且不能比现在晚一天以上），文字最多 500 个字符单位，表情 / 造型 / 提醒类型这些短字段最多 64。

数据库地址也别外传。

> **给以后改代码的人（升级兼容）**：规则只要求 `from` / `kind` / `ts` 三个字段，其他字段随意，
> 这是故意的——新版本可以给消息**加**字段（比如 `v`、将来的语音字段），老版本照样能写、能读。
> 消息字段**只能新增，不能改名或删除**；也不要在规则里加"禁止未知字段"之类的校验，
> 否则新老版本混用时消息会写不进去。详见 [upgrade-compat.md](upgrade-compat.md)。

## 第 4 部分：复制数据库网址

1. 点 **数据（Data）** 标签。
2. 顶部有一行网址，长得像：

   ```
   https://你的项目-default-rtdb.firebaseio.com/
   ```

3. 点旁边的复制图标，把它复制下来。**两个人要填同一个网址**，可以用微信发给对方。
   - **不要复制浏览器地址栏**：地址栏里是 `console.firebase.google.com/...` 开头的控制台网址，填进去是连不上的。
     要的是数据页面里面、以 `https://` 开头、`firebaseio.com`（或 `firebasedatabase.app`）结尾的那一行。
   - 如果你的网址是 `...firebasedatabase.app` 结尾，说明位置没选成美国，也能用，照样填即可。

## 第 5 部分：安装 App

两个人都要装。安装步骤（下载、拖进「应用程序」、第一次打开时放行）在 README 里，两边都照着做一遍：
**[README 的「安装」](../README.md#安装3-步)**。要点：一定要先拖进「应用程序」再打开；macOS 15 / 26 要在
系统设置 → 隐私与安全性 里点「仍要打开」。

打开后 App 没有程序坞图标，只在屏幕右上角**菜单栏**出现一个 🍊。

## 第 6 部分：在 App 里配对

第一次打开会弹出**欢迎窗**：选模式 → 选角色 → 选城市（可跳过）→ 配对。以后可以在菜单栏 🍊 → **设置… → 通用** 里修改，
字段完全一样。

1. **模式**：两个人要选同一种——**情侣** 或 **朋友**。（**一个人** 模式不需要 Firebase，也就不用看这份说明。）
2. **角色**
   - **情侣**：一个人选 **"我是噜噜"**，另一个人选 **"我是噜妹"**（两个人必须不同；角色决定你占哪一边）。
   - **朋友**：随便选，两个人选同一个也可以。
3. **配对码**（24 位）
   - **情侣**：**只让其中一个人**点 **生成**，点 **复制**，用微信发给对方；另一个人把它填进配对码框里（不要再点生成）。
   - **朋友**：一个人点 **生成** 再 **复制** 发给对方；**另一个人**复制收到的配对码后点 **粘贴**（不要点生成——
     朋友模式里「生成」和「粘贴」决定了谁占哪一边）。
   - 框下面显示"配对码没问题 ✓"就对了。配对码由大写字母和数字组成，**不含 0、O、1、I**（免得看错），
     **不分大小写**、也不在意空格——手打或者微信里转发时大小写变了也没关系。
4. **Firebase 数据库地址**：两个人都粘贴第 4 部分复制的**同一个**网址（以 `https://` 开头）。
5. 点 **开始**（设置里是 **保存**）。菜单栏 🍊 里显示"对方在线"就说明连上了；**双击**宠物打开传话面板，
   点 **"❤️ 发送爱心"** 或 **"去找TA 🏃"** 试试吧！（单击宠物只是在自己桌面上逗它玩，不会发消息。）

> 配对码就像你们俩的"钥匙"，不要发到公开的地方。

**验证一下是不是真的连上了**（两个人都做）：

1. 点菜单栏 🍊，看**最上面一行**：显示 **"对方在线"** 就是两边都连上了（"等 TA 配对中…"表示 TA 还没来过；
   "对方离线"表示 TA 来过但现在没开 App）。
2. **双击**宠物打开传话面板，点 **"❤️ 发送爱心"**：你的宠物会跑去 TA 的桌面，TA 那边点"收到 ❤️"后，
   你的宠物回来说"送到啦"，就全通了。

**菜单里提示"⚠️ 配对冲突"**：两台电脑占了同一边。情侣模式是两个人选了同一个角色——让一个人改选另一个；
朋友模式是两个人都点了生成——让一个人改成点 **粘贴**（配对码不变）。解决后提示会自己消失。

## 第 8 部分（可选）：网页版的手机 / 后台推送

只有用**网页版**、又想在页面关着（或手机锁屏）时也收到 TA 的消息、TA 叫你喝水、眼药水提醒，才需要这一步。Mac App 不需要、也不受影响。
推送要在 Firebase 上跑一小段云函数（`functions/`），所以项目要升级到 **Blaze（按量付费）**方案；我们的用量在免费额度里，正常是 0 元（见下面「费用」）。

**规则不用改**：订阅存在 `pairs/<配对码>/push/…`，眼药水的推送记录在 `pairs/<配对码>/tools/…/eyedrops/pushed`，都在上面那段规则已经允许的 `pairs/$code` 下面；
云函数自己的小索引 `pushIndex` 在根上，规则不让任何客户端读写（云函数用管理员权限，不受规则限制）。

一次性设置（管理员在 Mac 上做，按顺序）：

1. Firebase 控制台 → 左下角 **升级（Upgrade）** → 选 **Blaze**，绑一张卡；建议在 Google Cloud 控制台的 **结算 → 预算和提醒** 设一个 1 美元的预算提醒。
2. 终端：`npx firebase-tools login`（`deploy_web.sh` 用过就不用再登）。
3. `scripts/push_vapid.sh`：生成推送密钥，私钥存进 Secret Manager（`LULUPET_VAPID`），公钥写进 `web/js/net/vapid.js`（公钥可以提交）。
4. `scripts/deploy_functions.sh`（数据库网址以 `firebasedatabase.app` 结尾的，加 `--region <网址里的地区，比如 europe-west1>`）。
5. `scripts/deploy_web.sh`，让网页版带上新公钥。
6. 每台想收推送的设备：打开网页版 → 设置 → **手机 / 后台提醒** → 打开「手机 / 后台也提醒我」，允许通知。
   - **iPhone / iPad**（iOS 16.4 以上）：必须先在 Safari 里点 **分享 → 添加到主屏幕**，从主屏幕的图标打开，再去设置里打开。普通 Safari 标签页里没有推送。
   - 电脑上的 Chrome / Edge：浏览器开着（哪怕页面关了）就能收到。

收到什么、什么时候不推：

- TA 的文字 / 表情 / 爱心 / 来访，TA 叫你喝水 / 起来动动（带「马上 / 等会儿」按钮），TA 对你提醒的回复；眼药水到点没打卡（「滴了 / 等会儿」，15 分钟后再推，最多 3 遍）。
- **哪台设备正在用就提醒哪台**：每台设备会记下最近一次有人用它的时间（`pairs/<配对码>/devices/<座位>/<设备>`，Mac 0.19 起也写）。你 3 分钟内用过别的设备（Mac 或电脑上的网页版）就不推，免得重复；手机上噜噜正开着也不推。家里的 Mac 醒着但没人用，照样推到手机。设置里可以关掉「只在我电脑不在线时提醒」。
- 你开着勿扰 / 专注时：默认静音推送，也可以选「不推送」。眼药水照常（和 App 一样）。
- iPhone 的通知上没有按钮：点一下打开噜噜，里面的气泡上有按钮。

## 第 9 部分（可选）：部署网页版

网页版（`web/`）放在你们自己的 Firebase 项目的 **Hosting** 上，网址是 `https://<项目 ID>.web.app`，免费方案就能用。管理员在 Mac 上做一次：

1. 把项目 ID 写进本机文件（不会进仓库）：`mkdir -p ~/.config/lulupet && echo <项目 ID> > ~/.config/lulupet/firebase_project`
   （项目 ID 就是数据库网址里 `-default-rtdb` 前面那段）。
2. `npx firebase-tools login`，用管这个 Firebase 项目的 Google 账号登录。
3. `scripts/deploy_web.sh`。以后更新网页版也是这一条；想先试新版本不影响正式网址，用 `scripts/deploy_web.sh --preview <名字>`（30 天后自动失效）。

怎么在工作电脑和 iPhone 上用，见 [README「网页版：工作电脑和手机」](../README.md#网页版工作电脑和手机)。

## 费用

免费的 **Spark 方案**就够了，不用绑信用卡（只有第 8 部分的网页推送需要 Blaze，用量也在免费额度里）。实时数据库的免费额度大约是：
存储 1 GB、每月下载 10 GB、同时在线连接 100 个。
两个人戳一戳、发消息，每月用量通常只有几 MB，远远用不完。

## 常见问题

**菜单栏 🍊 最上面一行显示什么，该怎么办？**

下面是 App 里的原话（🍊 变成 🍊! 时也会写原因）：

| 菜单里显示 | 意思 | 怎么办 |
|---|---|---|
| 连接中… | 刚打开，正在连 | 等几秒 |
| 未连接：数据库地址有误 (HTTP 404) | 网址不对，Firebase 找不到这个数据库 | 重新复制第 4 部分的网址（**不要复制浏览器地址栏**），两个人填一样的 |
| 未连接：数据库地址格式有误 | 网址不是 `https://` 开头，或者多了奇怪的字符 | 同上，前后不要有空格 |
| 未连接：数据库规则拒绝访问 (HTTP 401) / (HTTP 403) | 安全规则没发布，或者不是上面那一段 | 第 3 部分重新粘贴规则并点 **发布**（没发布时是锁定模式，所有读写都被拒绝） |
| 未连接：数据库规则缺少 ts 索引 (HTTP 400) | 规则里少了 `".indexOn": ["ts"]` | 第 3 部分整段重新复制规则（别漏掉任何一行）并发布 |
| 未连接：网络断开，正在重试 | 电脑没网，或者网络拦了 `firebaseio.com` | 检查网络；公司网络、代理或 VPN 有时会拦，换个网络试试；在中国大陆要能访问 Google 服务的网络（它会自动重试） |
| ⚠️ 配对冲突：两边占了同一边，请一方改成粘贴配对码 | 两台电脑占了同一边 | 情侣：两个人选了同一个角色，让一个人改选另一个；朋友：两个人都点了"生成"，让一个人改成点 **粘贴**（配对码不变）。解决后提示会自己消失 |
| 对方在线 / 对方离线 / 等 TA 配对中… | 正常状态 | "等 TA 配对中…"= TA 还没来过；"对方离线"= TA 的 App 没开或电脑睡了 |

**两边都显示"对方在线"，却都说对方离线 / 互相收不到**

这种情况一定是**配对码不一样**：两边各自连上了数据库，但进了不同的"房间"。两个人都打开 设置 → 通用，把配对码一个字符一个字符对一遍
（或者让一个人点"复制"，另一个人整个重新粘贴）。配对码只要差一个字符就是两个房间；大小写和空格不影响。

**一边显示"在线"，另一边收不到**

多半是配对码或网址不一致，两个人都打开设置对照一下。

**对方显示"离线"**

对方的 App 没开，或者电脑睡眠了。这时发的消息会保存在数据库里，对方下次打开 App 时会收到。

**Firebase 发来邮件说"规则不安全 / 公开访问"**

可以放心。Firebase 看到规则里没有登录检查，会定期发这类提醒邮件（控制台里也会有黄色警告）。这套规则靠随机的配对码保护：
没有配对码的人读不到、写不进你们的数据，所以不用管它。

**打开时提示"已损坏，无法打开"**

见 [README 的「安装」](../README.md#安装3-步)：在"终端"里运行下面这行（去掉下载带来的隔离标记），再打开一次：

```bash
xattr -dr com.apple.quarantine /Applications/LuluPet.app
```
